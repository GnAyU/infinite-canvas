# How Local Codex Connects to the Canvas

## Current web-only configuration

Canvas Agent and the local proxy are **unsupported in this configuration**. The web app does not connect, probe or auto-reconnect to companions; imported flags and connection links do not enable them. Companion findings are mitigated by non-use, not repaired. Stop separately running companions and explicitly forget obsolete local connection values if no longer needed; existing residual tokens are not silently erased.

Model scripts and canvas plugins are opt-in **fully trusted page code**, not a sandbox. Approved code can read persisted provider/WebDAV secrets, any residual Agent token, page data and session-memory keys, issue requests and alter the app. Content digests identify exact bytes, not publisher authenticity. Import, discovery and preview do not execute code. Changed content needs renewed consent; reload requires consent again. Versions with unbound executable module dependencies are disabled, including the markdown `marked@14` and panorama `three@0.180.0` CDN cases.

New API/WebDAV credentials stay in page-session memory by default. Explicit “remember on this browser” stores the confirmed values in plaintext, not encrypted storage: browser-profile access and trusted extensions/scripts can expose them. Legacy plaintext remains usable and stored until an explicit keep/forget choice. Forget removes stored secret fields, not channels, projects, assets or media; it cannot undo earlier disclosure or revoke code that already ran.

Default config exports omit credential fields, credential-bearing addresses and executable bodies; review remaining user text before sharing. Full sensitive export needs separate plaintext/share-risk confirmation each time. Config import does not grant execution or remembering consent. An import missing a required recipient address is rejected as a whole before writes; re-export with the address or manually reconfigure the channel. Supported omitted-secret imports preserve credentials only for unchanged exact identity and recipient, including path. Explicit empty strings clear the corresponding secret.

## Historical upstream behavior — not supported instructions

The remainder describes **Historical upstream behavior**, not the current supported integration or an assurance about companion security. Do not use these historical token-bearing routes as connection instructions.

Historically, Codex did not control the browser DOM or simulate mouse actions. A local `Canvas Agent` bridged Codex tools and the React state that owned the canvas.

```text
Codex or browser side panel
        ↓
Local Canvas Agent
        ↓
Browser canvas React state
```

## Two entry points

From a local Codex conversation, the `infinite-canvas` MCP tools call Canvas Agent's `/api/tools` endpoint. Common tools read canvas state and selection, create or update nodes, connect nodes, and start image or text generation.

From the browser side panel, the browser sends a turn to `/agent/codex/turn`. Canvas Agent starts or reuses `codex app-server --stdio` and provides the same MCP tools to that conversation. Canvas writes still follow the same path: `Codex → MCP → Canvas Agent → browser`.

## Browser connection and state

Canvas Agent listens on `http://127.0.0.1:17371` by default and generates a connection token. The browser opens an authenticated SSE connection:

```text
GET /events?token=xxx&clientId=xxx
```

The browser pushes snapshots to:

```text
POST /canvas/state?token=xxx&clientId=xxx
```

Snapshots contain the canvas ID and title, nodes, edges, selected node IDs, and viewport. Canvas Agent keeps the latest snapshot in memory, so tools read structured state rather than the DOM.

## Applying operations

For a node creation, Codex calls an MCP tool, Canvas Agent converts it to `canvas_apply_ops`, sends an SSE `tool_call`, and the browser applies operations such as `add_node`, `update_node`, `delete_node`, `connect_nodes`, `set_viewport`, and `select_nodes`. The browser posts the result to `/canvas/result`, which completes the MCP call.

Writes are automatically confirmed by default. Switch the side panel to manual confirmation to approve each write. The frontend also stores the snapshot before the latest Agent operation so it can be undone.

## Historical security notes, not current guarantees

Loopback binding, token checks and browser confirmations in the historical design are not a sandbox, independent origin enrollment or proof that companion risks were fixed. This fork does not support companions. Do not infer that hosted page code cannot access keys: provider/WebDAV secrets may remain as legacy plaintext or be explicitly remembered in the browser, and fully trusted page code can also access session-memory keys and residual tokens. Existing historical approval/undo controls do not change that boundary.

In short, reads flow from browser snapshots through Canvas Agent and MCP to Codex; writes flow from Codex through MCP and SSE back to browser React state.
